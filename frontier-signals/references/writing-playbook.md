# 写作手册

## 动笔前写七行

只在内部完成：

~~~text
读者是谁，这件事会影响他的哪项选择、成本、工作、机会或风险
触发这篇文章的新闻
全文靠哪一个具体问题或冲突往前走
最硬的三件材料
一句判断
判断的边界
最自然的收束；确有未解决冲突时再记录问题，可留空
~~~

七行里没有具体名词、动作、数字和来源，说明还没准备好。第三行是内部推进线，不是公开标题或固定提问。每一节都要回答它的一部分，或让读者自然追问下一步；不要把事件、机制、影响和边界当成四个必须依次填写的抽屉。

## 标题

先写三类候选：

- 事实型：对象 + 已核实变化 + 直接后果；
- 判断型：事件 + 被忽略的限制或机制；
- 问题型：明确冲突 + 文章能够回答的问题。
- 传播型：具体主体 + 强数字、意外后果或正在扩大的冲突。
- 机制型：清楚实体 + 具体机制 + 有证据支撑的反直觉后果。

标题建议 14–30 个中文字符，最多使用一个标点转折。主体尽量出现在前半句。

每个候选标题内部按五项打分：一眼能懂、与读者有关、愿意点开、适合微信搜索、正文能够兑现。标题是流量入口，不需要故意写得平；它可以有情绪、悬念和戏剧性，但不能偷偷升级新闻状态。

吸引力优先来自“谁做了什么，以及哪里出人意料”。时间间隔只有在比较对象写清、而且正文真正解释了这个间隔时才能承担标题钩子；不写“只隔三周”“又更新了”一类读者看完仍不知道发生什么的标题。

report 标题要覆盖全文的中心变化，不要只抓某一节的边角，也不要把两到四个维度全部塞进标题。选择一条能统领全文的动作、冲突或结果，其他取舍留给正文。

情绪词不设固定黑名单，逐个检查是否有工作。“刚刚”需要真的刚发生，“突发”需要事件突然且重要，“急了”需要有主体反应支撑。“史上最强”“全球第一”“首次”“最大”要写清比较范围并保留发布方归属。媒体独家可以用“曝”“据报道”“消息称”“或将”，它们既是吸引力，也是事实边界。问号不能把传闻洗成事实。

机制型标题只在正文真正沿这条机制展开时使用。它可以预告反直觉后果，不能复刻竞品句式、拟人化胜负或把局部机制写成“人类已经怎样”的普遍结论。

微信搜索更接近站内检索，不等同网页 SEO，但同样依赖清楚的实体和关键词。公司、产品、模型或人物名称尽量进入前半句，再接动作、数字或后果。不要为了好奇心把报道对象藏到标题末尾。

## 第一屏

第一屏通常用两至三段覆盖：

1. 用一个已核实动作或数字交代新闻；
2. 说明这会影响哪类目标读者的什么，以及为什么现在需要知道；
3. 给出 Frontier Signals 的判断与边界。

这是信息覆盖要求，不是固定段数。不要先介绍栏目，不回顾整个 AI 历史，不预告“本文将从三个方面展开”。

通常在开头约 120 个中文字符内让报道主体完成一个明确动作，再给一项最能说明新闻性的数字、变化或冲突。行业背景最多先用一句，不能让竞品名单抢走主角。判断与边界可以在随后几段展开，不必全部压进第一句话。

不默认添加“30 秒速读”卡。标题、开头和判断已经能完成这三件事时，摘要卡只会再说一遍。较长文章确实需要阅读地图时才使用，而且每条必须提供正文开头尚未交代的信息。

核心判断始终保留在 `article.md` frontmatter 与正文相应位置，不必每篇都公开成独立的 The Signal 卡。新闻本身和第一节已经能自然交代判断时，直接把判断写进正文，不再重复制作卡片。

读者相关性要写成具体后果，不写成“这件事与你有关”的口号。可以说明某类人的预算、产品选择、工作步骤、机会或风险怎样变化，但不必频繁使用“你”，也不必把普通新闻评论改成教程或建议清单。文章天然值得转发的原因，应是读者能想到“这会影响我认识的某类人”，不是正文请求点赞、转发或代入。

机制型文章可以在三至五个短段内依次交代动作、机制、反制或限制，再压出全文唯一的核心矛盾。它是技术攻防稿的一种进入法，不是固定模板；第一屏仍要写清受影响角色与事实边界。

## 用一个矛盾带动机制型文章

模型、协议、安全和基础设施报道容易写成几块并排的说明。动笔前只选一个能覆盖全文的主矛盾，例如“系统依靠同一项机制获得能力，这项机制也留下了最直接的失效方式”。主矛盾必须来自当前材料，不能为了戏剧性临时制造。

正文优先沿“机制如何成立、同一机制怎样暴露失败面、成本落到谁身上、这改变了什么具体取舍”向前走。每扩大一层，都要由上一层机制或后果承接。小标题直接写本节新增的动作、结果或冲突；把小标题单独连读，也应能看见论证在推进。

解释陌生机制时，先用一个最小输入或任务，让读者看见系统实际做了什么。必要时可以给示意数字，但必须明确它只是帮助理解的假设。日常类比最多承担一次理解跃迁，下一段立即回到正式概念、真实数据和适用边界。

密集解释之间可以有一句短停顿或轻微幽默，让事实自身的反差帮读者换气。它不是固定模块，不承担新结论，也不能复制其他媒体的梗。观点放在材料已经托住的位置，不能因为例子顺畅就突然上升到人类、语言、文明或时代尺度。

## 正文顺序

bulletin 通常覆盖：

1. 发生了什么；
2. 这项变化怎样进入真实使用；
3. 读者现在该观察什么。

report 通常覆盖：

1. 事件和时间线；
2. 技术或商业机制；
3. 竞争关系与受影响角色；
4. 反方解释、限制和后续指标。

profile 通常覆盖：

1. 当前动作；
2. 人物或公司的关键时间线；
3. 技术、产品和组织选择；
4. 代价、分歧与其他解释；
5. 这次变化会把他们带到哪里。

这些是内部覆盖项，不要求固定节数、标题或顺序。结构服务材料，不强行凑齐；每节只完成一个任务。

逻辑上需要单独保留 claim 与图片归属，但公开阅读时只是上一节的自然延续，就继续写在同一 Markdown 小节，不额外增加 H2。不要省掉真正承担转场作用的小标题。

公开小标题优先写成“报道主体 + 动作、结果或明确问题”，让读者知道下一节具体会回答什么。`发生了什么`、`为什么重要`、`边界在哪里`、`值得关注` 可以留在内部提纲，除非它们在当前文章里确实比具体标题更清楚。不要为了活泼硬造隐喻或悬念。

小标题按字面理解也要成立。不要为了制造活人感，临时把抽象现象拟人化、发明动词或使用需要读者猜意思的俏皮话。读者如果必须看完正文才能明白标题在说什么，就改回具体主体、动作和结果。

## 段落

- 段落以讲完整一层意思为准，不设字符配额，不拆散主语、条件、比较关系和因果。
- 一段增加一件新东西，可以是事实、动作、解释、区别、后果或疑问。
- 连续两段只换说法时，合并或删除后一段。
- 先让主语和动作出现，再补时间、条件和原因。
- 单句成段只留给真正需要停顿的判断。
- 图前解释为什么要看，图后说出图改变了哪一部分判断。
- 加粗放在证据已经出现之后，用来收住一次机制转折或判断；它不能代替论证，每个主要逻辑转点最多一处。所有重点统一写成 `**重点**`，正文不使用彩色字体。

手机稿通常一段一到两句，长短跟着材料变化。连续几个长段都塞入多个数字、条件和结论时，按信息动作拆开；连续几个短段只剩口号或半句话时，把完整关系接回来。目标是扫读时不迷路，不是把每句话削短。

## 写技术

先写任务，再写能力：

差的写法是“模型支持 function calling 和长上下文”。

更清楚的写法是“它可以先读取仓库，再调用测试工具检查补丁。任务中断以后，应用仍要自己保存上下文”。

陌生概念确实难懂时，可以用一次准确的日常类比帮助读者入门，下一句就回到“运行层”“运行时”“模型适配器”“工具权限”等正式名称。不要让“大脑、底盘、工具箱、操作手册”之类抽象类比贯穿全文，也不要用类比替代产品实际做了什么。

解释一个新机制时，优先写清正常状态、新机制介入哪一步、单次选择怎样变化、累积后出现什么结果，以及同一介入点可能留下什么失败面。攻击工具、改写工具或演示已经出现，只能证明有人在尝试，不能替代匹配条件下的有效性测试。

基准分数后面继续回答：

- 测了什么任务；
- 由谁运行；
- 配置是否一致；
- 与真实工作的距离；
- 哪项失败信息没有公开。

数字段后面紧跟一句白话解释，说明差距对应什么任务或限制。解释不能超过数字本身能证明的范围；单项榜单不能直接推出“综合最好”“生产最稳”或“最值得迁移”。

## 写观点

观点段至少包含：

1. 一句直接判断；
2. 附近的事实依据；
3. 对谁产生什么后果；
4. 判断成立到哪里。

不要先捏造一个读者误解，再用“其实”“真正的”翻案。直接说判断，随后给依据。

反方段要把最有力的理由写准确。不要用一个明显愚蠢的观点充当反方。

`article.md` frontmatter 与 `source-notes.md` 中的判断边界保留给校验和编辑复核，不在成稿里单独渲染“判断边界”提示框。确实影响读者理解的限制，应自然写进对应事实或观点段。

## 自然中文

把读者当成坐在旁边一起看新闻的人，但只把核实后的信息和整理后的判断告诉他。聊天感来自自然的句子、具体的信息和清楚的取舍，不来自“我更在意的是”“这里先别急着下结论”“这笔账可以算一下”等思考路标。语气松一点，事实仍要准；不要为了显得亲切堆口头禅、网络梗或假装亲测。

把自己放在资深媒体编辑的位置，不在政策文件、研究论文和普通读者之间做生硬转运。先把术语翻成生活里的动作：`write action` 是“邮件真的发出去、文件真的被移动”，`development-time gate` 是“安全条件不过，训练就得停”。非常用词翻译后没有增加理解，就删掉。

新闻稿常见的“释放信号、引发关注、值得注意、业内人士认为、标志着重要转变”全部需要具体主语和动作。研究摘要常见的“现有材料表明、公开证据尚不能确认、该结论适用于”如果只是在展示查证过程，也移回内部事实台；正文直接告诉读者已经发生什么、还不知道什么。

生动、形象和有趣不等于加形容词。优先保留事实里的动作、反差和现实画面：一个模型训练真的停了两周，一封合作邮件真的可以从对话框发出去，一个作业提醒仍然有“跳过”按钮。幽默与锋芒停在事实允许的位置。

实用也不等于每篇都给教程。普通新闻至少让读者知道这会影响谁的哪项选择、成本、工作或风险；只有实测、教程或明确的决策评估才给操作步骤。

朋友式口吻不等于个人号口吻。品牌官号默认不用“我看”“我觉得”，也不为了拉近距离频繁喊“你”；判断直接说，读者需要代入具体产品入口或使用条件时才使用第二人称。句子长短服从信息关系，复杂事实可以用一句完整的话讲清，不能为了短而把主语、条件或因果拆散。

不要用“先别急着”“真正要争的”“从来不是”“说到底”一类句子表演聊天感或制造假转折。“不是……而是……”“不只是……而是……”“看似……其实……”及其换字变体同样删除。材料只支持一次发布时，不补出“默认选项之争”“默认执行层”“高频任务主力”“调用量决定一切”等可套用到任何模型新闻的宏大判断。

没有五件属于当前事件的具体材料，就不要用占位符和通用行业场景写样稿。客服、搜索、内容处理、代码辅助和 Agent 只有在材料确实交代了这些用途时才能出现；不能把一串常见场景当成新模型影响的证据。

清除这些模型痕迹：

- 商业闭环、底层逻辑、顶层设计、认知跃迁、赋能、抓手、全链路、组合拳；
- “更微妙的是”“还有一层”“值得注意的是”等洞察路标；
- 三项以上的同构排比；
- 没有来源的精确场景、天气、神态和对白；
- 把普通动作名词化，例如“完成了对流程的优化”；
- 用宏大抽象词替具体后果。

幽默只能压缩已经证明的事实矛盾。删掉幽默以后，证据链和判断必须仍然完整；严肃风险刚出现时，不用玩笑替它收尾。

检索路径、阅读顺序、媒体标题对选题的启发、作者的犹豫、自问自答与推演草稿，全部留在内部材料。只有文章本身是实测、调查或方法报道，而且过程本身构成证据时，才在正文写实际执行过的核验或测试步骤。

实测、抢先体验或产品对比稿可以使用编辑部的“我们”，但每一次都要对应真实动作，例如安装、配置、运行、计时、复测或核对结果。`我们都知道`、`我们不妨先看`、`我们更在意` 仍然只是写作路标，直接删掉。实测写法遵循 [hands-on-reporting.md](hands-on-reporting.md)。

模型和 Agent 更新不要默认收束成“是否迁移”。只有读者已经部署旧版本、替换成本与兼容问题真实存在，而且文章给出了切换依据时，迁移才是合适的问题。其余文章写清这次更新改变了哪项测试、任务范围、预算或观察指标。

新闻评论默认解释事件和判断，不自动转成读者操作指南。除非文章本身是教程、实测或明确的决策评估，避免“建议你”“先挑一批任务”“跑几次”“记录日志”“再决定”等动作清单。可以指出公开材料缺了什么，也可以明确选择证据更支持的解释；直接陈述编辑判断，不要替读者设计工作流来证明观点有用。

可以指出公开材料缺了什么，但直接写成“公开材料未披露 X”。可以给出分析，但直接写结论和支撑事实，不复述作者如何想到、比较或验证这个结论。没有数据支撑时，不用假设场景代替证据。

事实正确不等于适合公开。`现有材料只能确认`、`目前还缺两类信息`、`文档只定义了` 一类句子如果是在复述编辑部怎样查证，仍属于内部口吻。公开正文改写为读者直接需要的条件、结果和未知，例如“哪些套餐可用，OpenAI 尚未公布”。不要把 claim ledger 或事实审计报告润色后直接贴进文章。

## 引用

归属不是参考文献播报。已核实、无争议且能独立陈述的事实直接写，完整来源留在内部事实台。公众号正文默认不放“延伸阅读”；只有原文确实值得读者继续打开、方法与版权边界需要直接查阅，或用户明确要求时，才在文末保留一至三条关键链接。

直接引语、发布方自报成绩或承诺、单一媒体独家、匿名消息、争议或指控、观点，以及无法独立确认的说法，必须在句内保留最小必要归属。

“某媒体也把某词写进标题”“某媒体把价格叫作某名称”通常只是检索笔记。除非媒体叙事本身就是报道对象，否则删除。文档只是证据载体时，直接写其中已核实的信息，不用“模型卡写得很明白”“文档特别强调”等句子充当行文路标。

短引语只保留原话确实重要的部分。媒体和公司发布稿里的形容词不继承，把“革命性体验”还原成具体功能、价格、限制或时间。

## 结尾

结尾只选当前材料自然支持的一种落点：

- 一个有适用条件的产品或事件判断；
- 一项会验证或削弱判断的后续事实；
- 一个由正文已经讲清的具体反差或后果。

确有必要时可以自然合并两项，不要求每篇同时交付“决策含义 + 观察指标”。不要把所有文章都收成“接下来三件事会决定……”。

存在一个尚未解决、而且确实值得读者带着经验继续回答的冲突时，可以把问题自然写进最后一段。它是可选的，不能使用固定标题、独立互动卡或每篇复用的问句。

不要重新摘要全文，不请求点赞转发，不为了互动而提问，也不突然上升到时代或文明。文章已经结束时就停。

结尾每抬高一个抽象层级，都要有正文已经讲清的机制和具体后果承接。证据只够说明价格、使用条件、产品选择或风险时，就停在这些可观察变化，不把它们扩写成文化或人类命题。

正文结束后可以通过微信公众号原生功能添加一至三个相关话题。优先组合一个稳定大类与一个具体主体，例如 `AI安全` + `Anthropic`；不蹭与正文无关的热词。`wechat.topics` 只保存话题名称，不带 `#`。Markdown 和 HTML 不渲染假话题，发布前在公众号编辑器中添加并复核。

## 终稿冷读

完整朗读一遍。改掉需要回头找主语、一口气读不完或听起来像机构套话的句子，但不要以“更短”为目标机械拆句。

再做一遍“普通读者冷读”：假设读者不了解报道领域，圈出所有英文缩写、非常用词、行业黑话和抽象名词。每一处要么在附近用一句日常中文解释，要么删除。标题和第一屏不得要求读者先做功课。

最后做一遍“媒体人冷读”：删除作者内心独白、检索顺序、查证口吻和新闻稿腔。检查文章是否既准确，又有一个可复述的动作或画面；是否让读者知道这件事和自己有什么关系；是否自然、有趣、实用，而不是靠官腔维持分量。

冷读只看最终渲染出的公开正文，不看 frontmatter、source-notes 或校验报告。渲染器 0 错误、来源齐全、字数达标都不能替代这一遍读者视角复核。

逐段回答：

- 这一段靠哪件材料站住？
- 它给读者增加了什么？
- 这句话是事实、归属说法、分析还是建议？
- 这句话是在告诉读者事件与判断，还是在展示作者怎样找到、想到或验证它？如果是后者，移回内部材料。
- 判断是否比材料更大？
- 目标读者能否准确回答“这和我有什么关系”，而不是只知道行业很重要？
- 文中是否有一项具体信息，值得读者转给会受影响的朋友或同事？
- 换成任何 AI 新闻都成立的句子能否删除？

来源完全来自公开材料时，仍把完整 claim ledger 留在 `article.md` frontmatter 与 `source-notes.md`。公开正文按阅读需要决定是否保留少数链接，不自动追加来源列表，更不能把研究笔记塞进正文。

正文各节不追加“本节依据 [1][2]”一类索引行。来源统一放在文末。
