# 竞品实测笔记

这份笔记来自 2026-08-13 至 2026-08-17 的有限样本观察。它记录可复用的方法，不把少量样本概括成账号的永久定论。选题方向或平台习惯变化时重新采样。

## APPSO

### 观察到的样本

- 《一夜之间，GPT-5.6 来了，Codex 没了，Claude 急了》
- 《刚刚，GPT-5.6 正式发布，史上最强但被自己坑惨了》
- 《AI 时代求职指南》
- 《实测GLM-5.3: 在神仙打架的一周杀回国模顶流，还按下了重置键》
- 《马斯克要用 Grok 4.6 挤进「御三家」》
- 《首发体验 | DeepSeek Harness 来了，它不想做下一个Codex》
- 《Claude 的文字水印，成功把人类套路了》

### 文章特点

- 标题直接点出人物或产品、强动作和竞争位置，读者一眼知道新闻对象与冲突。
- 开头通常在三至五个短段内交代发布动作、时间差或一个反常事实，再进入证据。
- 手机段落多为一到两句，一段只推进一个数字、解释、结果或判断；没有为了短而把完整关系切碎。
- 截图、榜单、原帖和实测产物紧贴所证明的句子；必要的图注会补充测试条件或读图结论。
- 机构化“我们”主要出现在编辑部真实试用、对照和失败记录中，普通评论仍以直接陈述为主。
- 真正有用的观点常落在价格、产品选择、竞争关系、失败体验和普通用户会遇到什么。
- 结尾不固定：可以落到产品判断、行业变化、事实反差或一个当前事件独有的问题。
- 机制型文章会在开头快速摆出一个能自我推进的矛盾，再让每一节回答这个矛盾的新一层。Claude 水印样文的推进线是“水印靠重新分配词语选择写入，规避也靠重新选择词语破坏”。
- 陌生机制先用一个最小例子讲清，再用一次日常类比加深记忆，随后回到正式术语。例子和类比都服务同一个机制，不额外展开新的知识支线。
- 小标题本身承担判断和转场，不使用“技术原理”“影响分析”这类目录词。上一节留下的问题，会直接成为下一节的起点。
- 论证通常从机制走到攻防，再走到具体用户或创作者承受的后果。最后的价值判断出现得较晚，前面已经用足够材料把它托住。
- 密集技术段之间偶尔放一句短而轻的事实评价，让读者换气；这种句子不负责证明事实，也不按固定频率出现。
- Claude 水印样文使用约十张全栏图片，依次承担仓库证据、官方概念入口、token 机制、检测结果、攻防材料和作者观点来源。图片跟着论证换角色，尺寸与底色保留来源原貌，没有被统一改造成信息卡。
- 图注很少出现，只有来源或读图条件确实需要时才补一句。长解释后通常放一张能把机制变得可见的图，下一段再继续推论。

### Frontier Signals 应学习

- 保留对象清楚、进入新闻快、原始材料多的编辑部节奏。
- 先让读者看见界面、任务或结果，再解释陌生架构；抽象技术最多用一次准确的日常类比做入口，随后回到正式概念，不让“大脑”“底盘”“工具箱”代替产品结构。
- 用截图和图表证明，不用一长串引用压读者。
- 实测同时展示成功、失败、耗时和兼容问题；图注只补新信息。
- 允许事实自身带出幽默。
- 为机制型文章只选一个主矛盾。第一屏交代新闻、反常之处和这个矛盾，正文不再并排展开四五条同权重结论。
- 用一个带具体输入与选择的最小例子解释技术，再回到正式名称。类比最多承担一次理解跃迁，不能取代机制。
- 让小标题继续论证，例如“主体 + 动作或结果”，读者只看小标题也能看见文章怎样向前走。
- 把观点放在材料之后。先让读者理解系统怎样工作、哪里会失效，再说它把成本或选择交给了谁。
- 让图片也沿主矛盾推进。先证明事件，再解释机制，随后展示反制或限制，最后才使用人物、现场或观点来源帮助收束。
- 混用不同角色的原生素材建立节奏，保留网页、论文、产品和演示各自的视觉语言；栏目品牌不必压过证据。

### 不照搬

- 不机械继承“刚刚”“史上最强”“急了”等词。事件确实刚发生、比较范围明确或主体反应有材料时可以使用；否则换成正文能够兑现的动作、数字或后果。
- 不复刻红色像素卡、meme 密度和原句。
- 不让热闹的网友反应替代产品限制与独立核验。
- 不从单项榜单、一次 Demo 或主观画面观感推出“综合最好”“首选”或稳定成功率。
- 不用网络梗收掉隐私、安全和其他会改变判断的严肃风险。
- 不复刻“成功把人类套路了”“好一场酣畅淋漓”等现成判断和停顿句，也不把“先给悖论、再给类比、最后升华”机械变成每篇模板。
- 不照搬高密度加粗、连续反问和翻案句。Frontier Signals 仍用更少的重点、更明确的归属和更早出现的事实边界。
- 技术机制只能推到材料允许的位置。不能因为一个例子讲得漂亮，就把产品限制上升为普遍的人类、语言或时代结论。
- 不复刻黑底、橙色小标题、固定全栏图序列和 meme 停顿。Frontier Signals 保留自己的浅色品牌系统，只学习图片紧跟论证、角色多样与裁切可读。
- 不把模糊截图、整页桌面长图或来源不清的 meme 当作移动端配图；图片数量也不能替代图片权利与事实作用。

## 新智元

### 观察到的样本

- 《Ilya 的首个模型来了！》
- 《LSTM 之父最新 97 页综述，Agent 如何真正学会自我进化？》
- 《Agent 拉爆算力？中国杀出新物种》
- 《刚刚，全球首台真 Agent 原生手机来了》
- 《震撼！OpenAI全面开源Codex Harness》（2026-08-21）

### 文章特点

- 选题集中在重量级人物、新模型、论文、资本和技术里程碑。
- 标题使用人物光环、数字和竞争冲突制造大事件感。
- 深色背景、金色品牌元素、创始人肖像和宇宙感封面强化视觉冲击。
- 正文大量使用 X 帖子、论文截图、人物图片和数据图。
- 文章会把单次新闻放进 AGI、Scaling、产业竞争等更大的叙事。
- Codex Harness 样文用一个日常矛盾开题：团队原有工作界面有业务上下文，通用聊天框却要求人先搬运上下文。后续章节按“聊天框的限制 → Harness 是什么 → 开源组件 → 企业案例 → 产品控制权”推进，主线清楚。
- 同一篇把抽象架构翻译成三个具体层级：脚本/CI 用 `codex exec`，程序内启动与流式任务用 SDK，深度嵌入产品用 app-server。每个组件立即配使用场景，降低了陌生概念门槛。
- 案例选择同时覆盖可量化结果与可想象界面：税务流程处理 7,000 份申报表、耗时约降三分之一；Cisco App Builder 与物流看板 Relay 则把“嵌入原工作流”变成看得见的交互过程。
- 配图采用长短交替：官方社交帖与官方文档承担发布依据，数据图和架构图解释机制，产品界面、终端和案例页面制造现场感；16 张图中约三成只是品牌、推广或节奏组件，并非事实证据。

### Frontier Signals 应学习

- 给真正重要的新闻足够的视觉和叙事重量。
- 人物报道先交代人物过去的选择，再解释这次动作改变了什么。
- 技术新闻同时照顾论文、产品、公司和竞争格局。
- 开头优先找到一条读者已经经历的具体矛盾，再用新发布解释这条矛盾如何被改写。这里可学习的是“原工作界面带着业务上下文，聊天框却要求人搬运上下文”的问题结构，不照搬原句或“天下苦”式口号。
- 解释平台型产品时，用“组件 → 适用场景 → 谁掌握什么控制权”的顺序，避免只列功能。组件数量少而角色分明时，读者更容易形成选择框架。
- 案例要一硬一软：至少一个可量化结果负责证明规模或效率，一个界面或流程案例负责解释使用过程。案例数据紧邻来源与适用范围，不能从试点直接外推成行业普遍结果。
- 图片按 `Signal → Evidence → Mechanism → Implication → Case` 排列。关键论断旁放一手来源；长截图只裁关键区域，保证 375 px 下可读；架构图只解释关系，不冒充效果证据。
- 保留 OpenAI 官方原文里的边界：开源的是 harness 与 integration surface；模型访问和 managed services 仍是分开的。写“全面开源”时必须说明全面到哪一层。

### 不照搬

- 不用“王者归来”“杀疯”“拉爆”等词替证据加戏；事实本身存在足够强的竞争结果时，可以用更有冲击力的标题，但第一屏必须兑现。
- 不把匿名消息写成已经发生的事实。
- 不用通用宇宙、粒子、机器人图制造廉价未来感。
- 不把每个产品更新都抬到 AGI 或文明尺度。
- 不照搬“震撼”“彻底颠覆”“提效核武器”“零门槛时代”“最强外骨骼”等情绪结论。Codex Harness 样文的事实大体成立，但这些词把“开放 harness 与集成层”放大成了整个软件范式已经被重写。
- 不把 `13.3% → 38.3%` 直接改写成“AI 聪明了三倍”。该数字来自 ARC-AGI-3 的特定 harness 设置对比，只能说明在这个评测与设置下，保留推理和上下文压缩显著改变结果。
- 不把“平台全面开源”写成模型和托管服务也开源。OpenAI 官方明确写明：开源层是 harness 与 integration surface，model access 与 managed services 分开。
- 不用商务二维码、品牌横幅、点赞引导和结尾装饰图打断技术论证。16 张图里真正强的一手证据只是少数；Frontier Signals 应减少纯装饰图片，用统一的来源、日期和证据等级标注提升密度。
- 不把官方演示、合作伙伴试点或第三方帖子放在同一证据等级。Cisco、税务试点、Relay 演示各自只能证明对应范围，不能共同推出“各行各业已完成重构”。

## 数字生命卡兹克

### 观察到的样本

- 《这个封装了我 3 年自媒体经验的 AI 热点网站，今天向所有人免费开放》
- 《我让网易 LobsterAI 每天帮我蹲卡兹克，自动总结、信息图、X 帖子，一次全搞定》
- 《分享一下我现在随时随地让 Agent 干活的远程操控方案》
- 《OpenAI 开源的这个安全插件，是每个 Vibe Coding 的人都必装的神器》

### 文章特点

- 选题常从作者真实使用的工具、流程和问题出发。
- 第一人称说明为什么做、怎么做、实际用了多少来源或步骤。
- 屏幕截图密集，文章跟着操作过程向前走。
- 会给出具体数字和取舍，例如来源数量、信息分级和每天筛选出的条目数。
- 可信感来自“我确实做过”和可复现细节。

### Frontier Signals 应学习

- 只有编辑部确实执行了实测，而且过程本身构成证据时，才记录环境、步骤、失败和成本。
- 实测或教程稿可以给可复现方法；普通新闻评论只提供可核验材料、编辑判断和边界。
- 写 Agent 时优先展示任务、工具、权限、状态和人工接管点。

### 不照搬

- 没有亲测时不用第一人称暗示亲测。
- 个人体验只能证明这次体验，不能自动代表所有用户。
- 教程细节不能挤掉新闻全貌和反方证据。
- 不使用“所有人必装”“一次全搞定”等无边界承诺。

## Frontier Signals 的合成方向

从 APPSO 取事实进入速度与材料节奏，从新智元取重要事件的视觉重量。只有文章确有编辑部实测时，才借鉴卡兹克的亲测细节与可复现方法。

最终成品保持自己的比例：

- 事实与上下文约占六成；
- 机制和影响约占三成；
- 明确观点与判断边界约占一成。

比例只用于编辑检查，不要求机械分段。文章中不提竞品，不模仿标题句式、栏目卡和封面构图。
