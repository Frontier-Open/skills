# 微信公众号草稿与发布

## 状态

每个渠道独立记录状态：

~~~text
local_draft
editor_reviewed
owner_approved
remote_draft
published
sent
failed
~~~

published 指文章已经公开可访问。sent 指已经向订阅者群发。两者不是同一个动作。

## 默认停止点

没有经过验证的官方连接器、服务端适配器或已授权浏览器会话时，停止在 local_draft。交付 HTML、Markdown、封面、正文图片和人工检查单。

不要使用隐藏接口，不复制浏览器 token，不把 AppSecret、access_token、Cookie 或二维码写进仓库、稿件和日志。

## 保存到远端草稿箱

执行前同时确认：

1. 目标公众号名称与主体；
2. 稿件 title、date、slug 和内容哈希；
3. 当前状态至少为 editor_reviewed；
4. 用户明确允许本次远端写入；
5. 授权会话属于目标账号；
6. 图片、封面和作者字段已经确定。
7. 网页、App、聊天端、API、地区、账号档位、Stable 或 Preview、价格与开放范围等易变状态已经在本轮重新核对，相关 `checked_at` 已更新。

`release.json` 的 `content_hash` 使用 `sha256:` 加 `signal.json` 精确文件字节的 SHA-256。稿件、媒体引用或发布字段变化后必须重新计算；批准记录只绑定对应哈希。

成功后保存 draft_id 或可核验的草稿截图、时间、操作者和版本哈希。远端出现同一版本时复用，不重复创建。

## 官方 API 路径

若目标账号拥有权限，服务端适配器需要：

- AppID 与 AppSecret；
- access_token 缓存和刷新；
- 接口 IP 白名单；
- 正文图片上传后的微信 URL；
- 封面永久素材 MediaID；
- draft/add 的返回 MediaID；
- 幂等键、失败状态和审计记录。

密钥只放服务端。Cloudflare 等无固定出口 IP 的环境要先解决白名单，不把问题留给重试。

账号权限因主体和认证状态而异。调用前在公众号后台确认草稿、发布和群发接口权限。缺少权限时回到人工流程。

## 人工草稿流程

1. 在浏览器打开微信公众平台并确认账号。
2. 新建图文，填写标题、作者、摘要和封面。
3. 粘贴 wechat.html 的富文本或按 wechat.md 录入。
4. 逐张上传正文图片，确认微信没有替换顺序或压坏小字。
5. 检查原文链接、声明和来源；如果结尾自然留下了问题，再确认它不是固定互动话术。
6. 在手机预览。
7. 只保存草稿，不点击发表或群发。
8. 记录草稿时间与版本。

网页粘贴后必须重新检查样式。相对路径图片不会自动上传，不能把本地 HTML 当成已经可发布。

## 公开发布

公开发布前重新请求明确确认，并展示：

- 最终标题；
- 目标公众号；
- 封面缩略图；
- 文章版本或哈希；
- 计划发布时间；
- 这是“公开发表”还是“群发给订阅者”。

请求确认前再做一次事实新鲜度检查。任何易变产品状态与送审版不同，都要先同步正文、标题、claim ledger、source-notes 和内容哈希，再退回 editor_reviewed；不能沿用旧批准。

确认后正文、标题、封面或关键图片发生变化，退回 editor_reviewed。不要沿用旧确认。

官方发布接口返回 publish_id 后，通过状态查询或回调确认结果。超时不等于失败，先查状态再决定是否重试。

## 失败处理

- 登录失效、验证码、频控或账号异常时立即停止；
- 图片上传失败时不提交缺图版本；
- 接口返回不确定结果时先查草稿或发布状态；
- 发现账号不对时不做任何写入；
- 发布后发现事实错误时先记录更正，再按平台能力更新或撤回。

## 当前工作区检查

每次使用都重新检查 live code。不要根据文档假设适配器已经存在。

在没有服务端微信客户端、审批记录和真实 draft_id 的情况下，任何“已发布”都属于错误陈述。
