# 视觉与公众号排版

## 品牌基础

沿用 Frontier World 当前品牌系统：

- Passage Blue：#155EEF
- Ink：#101114
- Canvas：#FAFAF7
- White：#FFFFFF
- Mist：#E8EEFF
- Muted：#5D626D

Passage 标志用于需要母品牌识别的场景。公众号新闻封面不固定放 Passage 图标，同时清楚显示 `FRONTIER SIGNALS` 与右下角 `FRONTIER WORLD` 两个文字品牌。

## 公众号正文

- 最大内容宽度按 677 px 设计；
- 正文 16 px，行高 1.85–1.95；
- 主标题由微信编辑器承担，HTML 不再重复大号 H1；
- 微信作者字段默认留空；更新日期由微信编辑器承担，HTML 和 Markdown 正文片段顶部不再重复显示；
- 封面只用于公众号封面字段，不再作为正文首图重复出现；
- 正文外层不铺背景色，沿用公众号编辑器的默认白底；
- 正文顶部只显示英文栏目名 `FRONTIER SIGNALS`，不追加“信号快报”“深度报道”“人物侧写”等中文翻译；
- 二级标题 22–24 px，使用一条克制的 Passage Blue 左竖线与 12 px 左内边距，不加底色、序号或装饰；三级标题 18–20 px；
- 正文使用 Ink，辅助文字使用 Muted；
- 蓝色只用于栏目标签、关键线和少量判断，不给每段加底色；
- 正文重点统一用 `**重点**` 局部加粗。每段最多一处、全文最多六处；正文不使用彩色字体，不强调整段，也不把粗体当作第二套小标题；
- 不使用固定的结尾提问卡、关注卡或留言引导卡；
- 段间距 18–24 px，图片区与正文保持明确呼吸；
- 独占一行的图片使用微信兼容的 section + img，不使用会被草稿接口清掉的 figure，也不套空段落；图片与相邻文字只保留一次 20 px 间距，不生成空白行；
- 行内代码只用无背景、无边框、无内边距的等宽文字，不做浅色胶囊。长模型名、字段名和命令参数允许 `overflow-wrap:anywhere` 安全断行；使用继承文字颜色，避免微信深色模式把代码切成亮色碎块或空白背景条；
- 所有样式内联，避免脚本、外部 CSS、复杂定位、Grid 和交互。

能让读者记住或产生共鸣的句子自然留在正文段落中，必要时按局部加粗规则强调。公众号正文不制作独立金句卡、引用块，不显示“金句”、`QUOTE` 或其他特殊标签。

## 30 秒摘要区

30 秒摘要区不是固定栏目。短 bulletin 和正文已经足够紧凑的 report 不使用；较长 report 或 profile 只有在摘要能明显降低阅读成本时，才可以使用一个浅色信息区，依次呈现：

- 发生了什么
- 为什么重要
- 一句编辑判断

每项保持一到两句。卡片只帮助读者进入文章，不能重复 thesis、开头或结尾，也不能为了栏目统一而出现。

## 封面

微信公众号封面使用 900 × 383，重要文字和主体放在中央安全区。

封面只放：

- `FRONTIER SIGNALS` 文字栏目名，使用正常西文字体，不逐字额外拉大字距；
- 核心标题通常不超过 24 个中英文字符；同时包含中英文双主体与必要报道状态时最多 32 个字符，必须直接出现报道主体名称；
- 一个证据型主体或一个原创解释型图形；
- 底部右侧的 `FRONTIER WORLD` 母品牌文字。

栏目名与母品牌都要在微信缩略图里清楚可辨。用字号、字重和 Passage Blue 建立识别，不增加翻译、副标题、图标或装饰口号。

封面不放发布日期、文章类型、`SIGNAL REPORT`、分隔线或其他说明性小字。`FRONTIER WORLD` 只作为右下角母品牌文字出现，不与栏目名或报道主体争抢识别。报道对象有清晰、权利可核的官方产品标志时，右侧主体优先使用该标志，保持原色、原比例和足够留白。

保持 Canvas、Ink 与 Passage Blue 为主。不要用通用机器人、发光大脑、宇宙背景、霓虹城市和随处可见的 AI 粒子。人物新闻优先使用权利明确的真实人物图；产品新闻优先使用界面、设备或核心结构。

需要原创概念主体时才调用 `imagegen`。生成式图片不生成文字，标题、标志和来源由确定性排版添加；只使用品牌标志和标题已经足够时，不为装饰额外生成图片。

## 正文图片节奏

图片类型按价值排序：

1. Evidence：官方网页、公告、模型卡、论文图、财报与产品界面的可读截图；
2. Explanation：能让机制、对照或失败面直接可见的官方图表、论文图、界面状态与编辑部实测产物；
3. Human：权利明确的创始人、团队和现场图片；
4. Atmosphere：只有前三类无法承担必要的非证据型概念表达时，才用 `imagegen` 生成最多一张无文字原创图。

机制型 report 的图片也要形成一条叙事线。优先依次回答“事件或产品是什么、机制怎样工作、哪里出现反制或限制、后果落到谁身上”。不要求每篇凑齐四类，但连续三张图不能只是同类网页截图或重复证明同一句话。

每张图只承担一个主要问题。一个原页面同时包含仓库信息、参数表、演示与评论时，按当前段落紧裁到必要区域，不把整页桌面截图缩成手机上无法阅读的长图。保留来源标识、时间、单位和理解结论所需的上下文。

正文图默认占满内容列并保持原始比例。官方图、论文图和产品截图保留来源自身的底色与配色，不为了栏目统一重染证据；栏目识别由标题、间距、图注和正文样式完成，不给每张图套装饰卡框。

普通新闻与分析稿通常每 450–750 个中文字符出现一次真正有用的视觉停顿。产品首发、界面导览和实测稿可以提高到约 250–450 个字符一次，或者在每个主要功能、对照结果和失败点之后放一张对应证据图。这些只是节奏参考，不是图片配额；没有新证据时不要为缩短页面塞图。

机制解释较密时，可以在一个长解释之后紧跟一张 Explanation 图，再用下一段说出图中最该看的结果。图前交代“为什么现在要看它”，图后推进判断；图片不能只充当黑白文字之间的休息区。连续两张图之间通常至少有一段新增信息，避免把文章变成截图相册。

产品界面本身构成新闻时，第一张有效截图尽量出现在第一屏附近。图片应紧跟它证明的句子，不把一批图统一堆到整节末尾。

需要把图片插入一节中间时，直接把 Markdown 图片放在它所证明的段落之后：

~~~markdown
这一段先交代为什么现在要看这张图。

![准确的图片 alt](images/evidence.png "只补充对象、条件或结果的图注")

下一段继续推进判断。
~~~

图片路径、alt、caption、credit、rights、purpose、generated 与 show_caption 同时登记在 `article.md` frontmatter 的 `media` 数组中。正文图片与 media 条目必须一一对应。解析器当前不保存 `source_url` 与 `crop_note`；这两项统一写入 `source-notes.md` 的图片记录，不在 frontmatter 里制造看似存在但实际被忽略的字段。

每张图片写清：

~~~text
path
purpose
alt
caption
credit
rights
generated
show_caption
~~~

每张外部图片另在 `source-notes.md` 记录：`path / source_url / checked_at / crop_note`。自有确定性图片至少记录 path 与生成源；外部截图必须记录原页、核对时间和精确裁切范围。

`generated` 只表示是否由生成式 AI 产生。官方截图、官方图片和确定性排版封面都填 `false`。

`show_caption` 默认 `false`。证据图、测试分组或界面状态离开上下文会难以理解时，可以设为 `true`，公开一条简短图注。图注只补充对象、条件或结果，不写“图源：”、版权署名、链接和研究过程，也不重复上一段。credit 留在 frontmatter，source_url 与裁切记录留在 `source-notes.md`；正文只按阅读需要保留少量关键链接。

同一篇文章可以混用源码或仓库截图、官方概念图、机制图、产品结果和人物现场，以建立视觉高低差。轻松图片或 meme 只有在权利清楚、事实本身确有反差、而且删除它会损失一层理解时才使用；不能靠网络梗替代机制图，也不能用来冲淡安全、隐私或法律边界。

图表必须保留坐标、单位、样本与时间范围。裁切不能改变原图结论。

## 截图

- 截图前确认页面版本和时间；
- “高清”必须同时通过源文件与移动端可读性两道检查。满宽横图存在更大官方原图时，至少保留 1354 px 宽的源文件，不先缩小或低质量重压；界面和文字截图优先使用无损 PNG，原图为 JPEG 时避免反复转码。
- 375 px HTTP 预览按 100% 缩放验收。支撑正文判断的界面文字、数字、坐标、单位和关键控件必须直接可读；像素尺寸很大但主体只占小块画面，仍不算高清。
- 只裁掉无关浏览器边框，不裁掉来源名、时间、单位和必要上下文；
- 裁切后让核心内容落在画面中央，左右留白尽量均衡；标题、关键文字、图表边界和必要控件必须完整，不得漏截，也不得贴近左右边缘；
- 社媒截图只能证明发帖者说过什么；
- 官方网页截图可以直接作为最终正文图。字太小时先用移动端视口重截，再紧裁到必要原文，并保留来源、标题、日期、单位和判断所需上下文；仍不可读时换一张官方图或放弃该图，不制作事实卡；
- 同一官方图包含连续界面状态且横排会让小字不可读时，可以从最高分辨率原图分别紧裁后纵向排列；不得锐化、AI 重绘或只做无信息的像素放大。把原图尺寸、最终尺寸和精确裁切范围写入 `source-notes.md`；
- 不移除水印或署名。
- 定稿前裁掉与证据无关的整块空白，但保留来源身份、标题、时间、单位、字段边界和理解结论所需上下文。裁切后更新 `source-notes.md` 中的 crop_note、图片尺寸、媒体哈希与整包哈希，再重做 375 / 677 px 预览；不能只改图片而沿用旧批准。

## 原创概念图

使用 Frontier Blue 作为信号，Ink 表示系统或限制，Mist 表示环境。图中结构应当直接对应文章里的事实关系。

只有文章存在官方截图无法承担的概念入口时才调用 `imagegen`，适合表现：

- Agent 的任务、工具、状态与人工确认图；
- 模型能力、成本与限制对比；
- 公司与产品的关键时间线；
- 从模型能力到真实业务结果的转换路径。

不适合生成：

- 没有数据的上升箭头；
- 看似复杂但无法对应事实的网络图；
- 只负责“科技感”的装饰图。
- 网页、表格、价格、跑分、接口字段和任何事实证据的仿制图。

## 竞品视觉借鉴边界

学习高频视觉停顿、证据紧跟结论、图片角色多样和原生素材优先。不要复刻竞品的黑底、橙色标题、meme 密度、图注样式、固定图片顺序或整篇构图。Frontier Signals 继续使用 Canvas、Ink 与 Passage Blue；样文只能帮助决定“这里需要哪种图”，不能决定“这张图要长得像谁”。

## 预览清单

在 375 px 与 677 px 检查：

- 无横向滚动；
- 小标题不出现单字孤行；
- 图片里的关键小字在 100% 缩放下仍可读，不依赖点开或双指放大；
- `show_caption: true` 的图注清晰且提供新信息，其他图片没有残留图注、署名或脚注行；
- 网页截图的核心内容在画面中央，左右留白均衡，没有文字、图表或控件被边缘截断；
- 链接有明显颜色或下划线；
- 深色截图周围有足够留白；
- 末尾来源列表没有挤成一团；
- 延伸阅读默认不出现；启用时只有一至三条短标签，不附出版方或研究笔记；
- 封面缩略图仍能看清对象与核心词。
